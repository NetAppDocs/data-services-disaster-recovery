= Switch Console agents when using NetApp Disaster Recovery
:hardbreaks:
:icons: font
:imagesdir: ../media/use/

[.lead]
You can use multiple Console agents in a single working environment to maintain access to resources during maintenance or if an agent fails. To avoid disrupting resource availability, switch agents carefully because each agent has a unique identifier. 

## Before you begin

* You must have xref:../get-started/dr-prerequisites.html#create-the-netapp-console-agent[added at least two Console agents for your working environment]. 
* Both Console agents must contain the same ONTAP clusters. 

## Steps

. In Disaster Recovery, select **Sites**.
. Change the Console agent for both the source and destination vCenters. Identify the vCenters that you want to modify, and then select the action menu for each vCenter and select **Edit**.
+
image:dr-sites-subnet-menu.png[Screenshot of the Sites dashboard]

. Select the Console agent that you want to use from the drop-down menu, and then reenter your vCenter user name and password. Select **Save**. 
+
image:edit-vcenter.png[Screenshot changing the Console agent]
. Repeat steps 2 and 3 for each additional vCenter you want to modify.
. For each modified vCenter, refresh the connection to discover the new Console agent. Repeat this step for every vCenter you've modified. 
. In Disaster Recovery, navigate to **Replication plans**.
. Identify the replication plans that you want to use to resume operations. Select the action menu `...` then **Refresh resources**. You can monitor the status of the jobs in **Job monitoring**.
